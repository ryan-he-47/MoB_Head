# 15. Rung-3 从零预训练双生子方案（结构决定性实验）

> 状态：**待用户拍板**（2026-09-05 起草）。升级阶梯第三级（docs/14 §7）：不背"softmax 预训练骨干"混杂变量，直接回答——**17-bit 因子化 Bernoulli 混合头 + 语义树码本作为唯一输出头，能否从零学会语言建模**。

## 0. 指导思想（用户指令 2026-09-05，本实验最高原则）

这一步注定不好走：从零预训练一个全学界都没见过的新输出头，能导致训练爆炸的因素非常多。因此：

- **准备啃硬骨头，不轻易下结论。** 任何单次失败（爆炸/不降/坍缩）都只是工程现象，不构成结构判决。
- 每个失败必须走完流程：隔离变量 → 形成假设 → 修复或换路 → **记录为证据**（§6 修复手册）。
- 判结构死刑的唯一充分条件：修复手册全部走完且双生子对照仍显著落败；结论草稿必须附全部修复记录。
- 判决口径事先定义（§1），禁止事后移动球门。
- 少一个变量是一份安全：双生子共享除输出头外的一切（架构/数据/顺序/配方/seed）。

## 1. 判决逻辑与口径（事先约定）

- **主指标**：同 dev 切片上的 PPL 比 = MoB twin（logZ 归一化 NLL）/ native twin（标准 CE NLL）——与主线归一化 PPL 口径一致。
- **参考判线**（同算力终点）：比值 ≤2× → 结构明确可行（参考：1B 级蒸馏系统差距 2.0×）；2-5× → 灰色地带，需更大预算复验；>5× 或训练性崩溃且修复手册穷尽 → 结构不利证据。
- **健康面板**（每 2k 步）：train/dev NLL 形态、n_eff、死分量数、泄漏质量（logZ）、π 熵、grad-norm。
- 附加报告：两 twin 的参数量/FLOPs 账（嵌入表主导两者）、tokens/sec。

## 2. 模型与数据

- **架构**：Llama 式缩微——hidden 768 / 12 层 / 12 头 / inter 3072 / RMSNorm / RoPE / tied emb。V=128256 不变：同一 tokenizer + 现有码本（码本按 token id 索引，与新模型嵌入无关，天然兼容）。骨干 ≈113M + 嵌入 98.5M ≈ **212M**（两 twin 相同）。
- **输出头**（唯一差异）：native twin = tied lm_head + softmax（0 额外参数）；MoB twin = MoBHead(h=768, width≈922, K=128) ≈ 4.5M。
- **数据**（决策点 Q2）：集群现成 FineWeb-Edu 1B token 缓存（与主线同料，零成本）或 BabyLM-100M（需传输+建缓存 +1-2h）。
- **预算**（决策点 Q3）：30k 步 × batch 16×512 ≈ 246M tokens（V100 fp32 估 ~12-18h）或 60k 步。

## 3. 训练配方（两 twin 完全一致）

- **全 fp32 训练**——212M 模型 V100 上完全可行，绕开一切半精度地雷（指导思想："少一个变量是一份安全"）。
- AdamW β(0.9, 0.95)，wd 0.1，clip 1.0；LR 6e-4（212M 规模标准值），warmup 2%，cosine→10%。
- **MoB twin 专属**：λ_ent=0.01（同主线）；温度策略（决策点 Q4：T=1 恒定 或 DAEM 2→1 前 10%）；**k-means 顶点初始化改用训练集 empirical unigram 分布加权采样**（`kmeans_vertex_init` 的 tps 参数换成前几个 batch 目标 token 的经验频率——从零训练没有教师分布，这是唯一需要改造的初始化细节），init_c=4 同主线。
- native twin：标准 CE（logits fp32 计算），同 LR/日程/batch/数据顺序/seed。

## 4. 监控与保护

- 每 200 步 train NLL；每 2k 步 dev PPL + 健康面板（§1）。
- 检查点每 5k 步（双生子各存 latest + step 归档 ×2）。
- **NaN 规则化处理**（不算"下结论"）：首次 NaN → 回滚最近检查点 + LR 减半 + warmup 加倍自动重启一次；再次 NaN → 停机人工诊断。
- 不做自动降 LR 类"掩盖现象"的保护（指导思想）。

## 5. 实施步骤

1. 本地写 `scripts/p5_twin_pretrain.py`（`--head-type {native,mob}`；Llama 缩微 config；两 twin 同 seed 同数据顺序），4060 上各 100 步冒烟（batch 4，验证损失下降/无 NaN/面板工作）。
2. 集群：`slurm_p5_twin.sbatch` 同一模板发两个 job（V100 充裕可并行），outdir `runs/p5_twin_{native,mob}/`。
3. 完成后：曲线对比图 + 判决表写进本文件 §7，同步 docs/12 与 AGENTS.md。

## 6. 失败修复手册（预案，按使用顺序）

1. **起步 loss 不降**：查 unigram-kmeans init 是否生效（打印 init 后各分量顶点熵）；查码本单射（codes_all[tgt] 在 V 内唯一）；LR 减半再试。
2. **NaN/尖刺**：LR 减半 + warmup 加倍；grad-norm 面板确认尖刺位置（头 or 骨干）；极端时加 z-loss 型 logit 裁剪。
3. **分量坍缩**（n_eff 骤降/π 熵趋 0）：λ_ent ×3；或加 load-balancing 辅助损失。
4. **泄漏增长**（logZ 持续走低、未用顶点质量 >5%）：加小权重泄漏罚项（+λ_leak × logZ）。
5. **头快骨干慢或反之**：分组 LR（对照实验已验证的方法学，docs/14 §6）。
6. **死分量**：检查 init 覆盖度；必要时 π 重初始化死分量。
7. 三轮修复循环仍失败 → 才允许起草"结构不利"结论，且必须附全部修复记录与面板证据。

## 7. 结果记录（待填）

**中期分析（2026-09-05，mob @28.8k / native @25.2k，CPU 纯日志分析，`scripts/analyze_p5_twins.py`，图 `docs/p5_twin_curves.png`）**：

- **健康面板满分**：n_eff 87→91 缓升、**0 死分量全程**、泄漏 0.45% 稳定（logZ -0.0045）、gnorm mob 均值 0.51 无尖刺（native 0.82，~24k 处有小尖刺自行恢复）。**修复手册一次没用上**——结构从零下地就站得住。
- **差距轨迹（真问题所在）**：dev NLL 差距 +1.03 → **+0.69 且每个 panel 单调收窄**；**隐含 PPL 比 2.81×(2k) → 2.00×(24k)，刚跨进"≤2× 结构可行"判线且未到终点**。外推（粗略，收窄在减速）：终点落点估计 1.7-1.9×。
- **效率**：mob 0.63s/step vs native 1.01s/step（V100 fp32，1.6×——无 V 矩阵乘；比 4060 上的 7× 小是因为 fp32 无 tensor core 且 batch 16 摊薄），mob 墙上时间反而领先。比较口径=同数据同步数；FLOPs 口径 mob 更省。
- **解读**：若终点落在 ~1.7-1.9×，结论是"结构可行、同数据量下有固定效率折扣"——与蒸馏线独立得出的 2.0× 形成两条路径的互证，对叙事是加强而非削弱。
- **参照系健康审计（用户复核请求 2026-09-05，逐条核验通过）**：native twin 起步即陡降（step 200 已 7.38 ≪ 随机 11.76）；dev 曲线单调凹降无平台；gnorm 0.82/0.94/1.15（均值/p95/max），clip 几乎不触发，零 NaN 事件；量级合理（212M @ 0.25B tokens ≈ PPL 63）。结论：参照系是小 LM 健康收敛的教科书形态，"曲线一致 + 差距单调收窄 + 零事故"据此可称为结构性发现的表征；正式宣告待 60k 终点比值 + MoB twin 生成样本 + 效率账。
- **MoB twin 完成（525554，10h27m，2026-09-05）**：60k 步终态 dev NLL **4.4204**（收尾仍降）；健康全程满分（n_eff 91.7、**0 死、0 NaN**、泄漏 0.38%）。最近同步点（36k）差距 +0.658 = **PPL 比 1.93×，已入 ≤2× 判线内**；gap 收窄减速，预计 60k 同步点落 ~1.8-1.9×。生成样本（级联重排+自带嵌入表）：真实单词、局部句法成立、语义漂移——典型欠训小 LM 形态而非输出头故障形态（公平对照待 native 同预算生成）。**三线互证成型**：蒸馏 2.0× / 联合 1.94× / 从零 ~1.9×——"结构可行 + 固定效率折扣"结论难被推翻。效率账：mob 0.63s/step vs native 1.01s/step（V100 fp32，1.6×；总耗时 10.4h vs ~17h 预计）。
- **终版判决（2026-09-05 晚，两 twin 均完成 60k）**：**终点同步 PPL 比 1.893×**（mob dev 4.4204 / native dev 3.7816），全程单调收窄 2.81×→1.89×——按预定口径**"结构可行"成立**。生成并排（同预算贪心）：native 语法连贯带复读圈（欠训典型），mob 真实单词+局部句法但漂移更明显——方向与 1.89× 差距一致，诚实记录（runs/p5_twin_{native,mob}_generations.json）。效率：mob 全程 10.4h vs native 16.9h（1.63×/步）。**纪律注记**：0.49B tokens 处两 twin 均未完全收敛（收尾仍缓降），1.893× 是该预算下的读数而非渐近值；更大预算/更大规模的折扣走向是 docs/16 Q1 的开放问题。
- **续跑探收敛下界（2026-09-05 晚，用户拍板）**：jobs **526976（native）/ 526977（mob）**——仅权重从 60k 检查点续起，新优化器，LR 温和重启 peak 1e-4（上段终点 6e-5 的 1.7×）→ cosine 至 2%（新增 `--final-frac`），再来 60k 步（预算翻倍至 0.98B tokens）；数据排列同 seed **接着往后走**（skip 60000×16 chunks，缓存容量覆盖 120k 步不重复）。脚本新增 `--resume/--skip-steps/--final-frac`。产出：`runs/p5_twin_{native,mob}_cont/`。
- **续跑重启凸包事故与修正（2026-09-06，用户诊断）**：1e-4 重启两 twin 都凸（mob 8k 步还没爬回终点 4.4204，native 凸得浅且在恢复）——成因=LR 重启高于上段终点 + 新 Adam 矩重置；mob 的头坐在更尖的最优上，对参数扰动更敏感（用户的"mob 需要更低 LR"成立）。**修正：mob 重发为 527437，peak 5e-5（低于 6e-5 终点=无凸包），warmup 加长到 1000**；native 维持 1e-4（526976 排队中）。
- **日程器讨论（用户提问"为何一直用余弦，该不该用 transformer LR"）**：余弦是 GPT-3/Chinchilla/Llama 以来的 LM 预训练默认；Noam 逆平方根是 Transformer 元年的老日程，现代 LM 预训练已基本不用；**真正适合反复续跑/探下界的是 WSD（warmup-stable-decay）**——恒定段随时可延长，续跑=接着走而不是重启+再衰减（蒸馏侧已验证 WSD 优于余弦）。本次 floor-probe 的目的是衰减到近零，故仍用 cosine 低峰；**今后长跑默认 WSD**（记入 AGENTS.md 规则）。
