# 16. MoB 头研究母题：开放问题纲领

> 定位（用户定调 2026-09-05）：MoB 头**不是**"理论上逼近但结构上低效的 softmax 替代品"——那是一个全新研究母题的自我矮化。目前唯一确立的事实是 **MoB 头可以用于模型预训练**（rung-3 从零双生子，健康全程、轨迹跟随参照系）。边界在哪、价值是什么、什么变体更强，全部未探索。本文档是开放问题的纲领清单，每条注明已知证据与所需实验。

## 0. 方法论纪律（两次用户纠正，长期有效）

- 未见收敛下界不报"天花板/固定折扣"：轨迹是轨迹，终点是终点。
- 任何失败先走修复手册，手册穷尽之前不作结构判决。

## 1. 已确立事实（截至 2026-09-05）

1. 蒸馏可行：1B 冻结骨干 + MoB 头，归一化 PPL 2.0×、级联解码有效保真 ~94%（docs/09）。
2. 从零预训练可行：212M 双生子，MoB twin 健康全程（0 死分量/0 NaN/泄漏 <0.5%），曲线跟随 native 参照系（docs/15）。
3. 联合共适应可行但收益薄（LoRA/全参末 4 层均饱和 ~-5% 密度；LoRA 低秩假设不适用本任务的证据在案，docs/14）。
4. 训练侧效率信号：twin 实验中 MoB 每步快 1.6×（V100 fp32；无 V 矩阵乘）；推理侧账见 docs/08。
5. 参照系健康：native twin 为小 LM 教科书收敛形态（docs/15 §7 审计）。

## 2. 开放问题（用户提出 + 补充）

### Q1 效率折扣与骨干规模的关系
- 折扣随 d_model/层数变化吗？更宽更深的骨干是否更能适应 MoB 头（h 几何更可塑）？
- 反向假设：17-bit 瓶颈的梯度回传会不会随模型变大而失效——驱动不了大模型训练？
- 实验：多规模从零 twin 阶梯（212M 已做 → 500M/1B）；观察折扣随规模的斜率。

### Q2 头的结构轴
- 宽度 vs 深度：**两臂消融已发**（见 §4），参数量对齐 ~51M，同 WSD 配方。
- K 与分量利用率：n_eff 91/128 的余量是数据/训练量不足还是结构冗余？
- 温度家族（DAEM 之于从零训练的意义未探）。
- **ECC 校验位（用户批准的探索性实验，2026-09-06 起冻结待命）**：校验位=数据位的确定性 XOR 函数——因子化混合对 XOR/奇偶结构最难表达（轴对齐模型的经典死穴），位级行为差异有强诊断价值；"传统编码算法当神经网络先验"是全新叙事。**状态：用户明确指示——可以做，但先别跑，等用户的实验计划。** 前置的 M 参数化基建（与多模型共用）已在进行中。

### Q3 码本轴
- 用更大模型的嵌入表建树（语义质量更高的树）会改变性能吗？现状：Llama-3.2-1B 表。
- 树构造算法本身：2-means 方向+median 平衡（现状）vs 谱方法 vs 端到端学码（码本可学习/在线重排）。

### Q4 价值与接口轴
- **空码是资源**：2^17-128256=2816 个未用顶点能否做词表扩展（新 token 免改树直接获码：领域词/控制符/水印位）？
- 输出空间可编程性：码即接口——位掩码=语义域约束解码、结构化生成、组合控制。
- 训练侧效率的正式量化（twin 观察 1.6×；大规模下是否保持/放大）。

## 5. 三头赛马计划（用户设计 2026-09-07，待磋商后开工）

**动机**：双联实验证明 deep 的劣势主要是高 LR 相位的优化假象（衰减段发力追近），且各头的 LR 舒适区不同——下一轮头结构对比必须 (a) 给深层头现代化梯度流改造，(b) 每头独立 LR 日程。

**设计**：SmolLM2-1.7B（原生受试，兼作弗兰肯斯坦基线）冻结基座，拖三个头同批数据流（paired）：
1. **对照臂**：原版 3 层 MLP 头（3072，SiLU）——同 Llama 主线规格；
2. **残差臂**：5 层 MLP + pre-norm（RMSNorm）+ 残差连接 + 输出前终 norm（用户路线 1）；
3. **SwiGLU 臂**：与 LLM 内置 FFN 同构（W3(SiLU(xW1)⊙(xW2))）输出 MoB 分量（用户路线 2）；
臂 2/3 参数量对齐（~30M 级），**每头独立 warmup/峰值/衰减日程**，峰值由本地 4060 扫描确定。
**判读**：以对照臂为弗兰肯斯坦基线（vs Llama 蒸馏受试的 2.05× 线），臂 2/3 的提升即现代化改造的价值；中途只报轨迹，收敛后判决（§3）。
**前置**：SmolLM2 预备 job（530685，权重+码本+缓存）完成后启动；LR 扫描协议（峰 {3e-4, 7e-4, 1.5e-3, 3e-3} × ~2k 步/头，看损失斜率+稳定性）在磋商中确认。
**磋商定案（2026-09-07）**：①浅层探针跑完不杀（shallow1l 给衰减尾）；②LR/架构搜索放**本地 4060 详细做**（让 HPC 歇额度——用户担心连轴转拉低账号 priority），扫描器 `scripts/p7_lr_scan.py`：4 头型（mlp3 对照 32.3M / resmlp5 51.2M / swiglu1-7300 49.6M / swiglu2-3690 50.1M）× 4 峰值 × 1200 步，**断点续跑**（每单元一个结果 JSON，重启自动跳过；用户睡眠时随时可杀，重跑同命令无缝续）；扫描用 Llama 基座（h=2048 与 SmolLM2 相同，LR 舒适度按架构转移）；③赛马步数：**本地搜出峰值后直接上集群 245k 全量**，一步到位定主导架构；④臂 2/3 参数量对齐 **~50M**（resmlp5-3072=51.2M、swiglu-7300=49.6M、swiglu2-3690=50.1M）。新头实现：`mob_common.ResMLPHead`（pre-norm RMSNorm+残差+终 norm）、`SwiGLUHead`（W3(SiLU(xW1)⊙(xW2))，h→hidden→h，残差堆叠）。

## 4. 实施记录

- 2026-09-05：头规模两臂消融以**双联形式**提交（用户巧思：蒸馏共享冻结骨干前向）——`p2_train_dual.py`：wide 4096×3（51.4M）与 deep 3072×5（51.1M）并挂同一基座，两份优化器，**完全相同的 batch 流（配对样本，消除数据顺序方差）**，成本实测 0.57s/step = 单跑的 1.58×（省 21%，低于预估的 1.2×，修正记录）。job **526516**，WSD 配方同 520825，1 epoch FineWeb 1B，结束自动对两臂各跑 p3_eval。`MoBHead` 新增 depth 参数（旧 checkpoint 兼容）；ECC 探索实验排在其后（码本追加校验列 + M 参数化）。
- 2026-09-05 双联中期趋势（72.2k/245k = 29%）：**wide 稳定领先**（agree 0.714 vs 0.696，dev_nll 3.377 vs 3.516，差 ~+1.5-2pt / 0.13 nats），n_eff 两臂相当（~74/128）；两臂均在恒定 LR 平台段——按 WSD 经验判决在衰减尾（159k 后），当前只报趋势不判决（纪律 §0）。
- 2026-09-06 双联 137k 同步位全面对照（`scripts/analyze_headscale.py`，原版 WSD 3072×3/32.3M 为尺）：**wide ≈ 原版（±0.005 振荡，+59% 参数零增益）；deep 稳定落后 ~1.7pt**。候选解释：①读出型任务的函数形式偏"宽基展开+线性读出"，加深只加优化难度；②任务信息天花板先到（续训 +0.004 / 联合 -5% / 加宽平 三线同指）；③混合族逼近能力的真实间隙（从零 twin 无蒸馏截断也有 1.89×，独立佐证）。**判决性探针（job 527923，用户点名："单隐层？甚至线性头？"；隐宽修正为 3072 与原版同宽以隔离深度变量）**：1 隐层 3072（13.4M）vs 纯线性头（4.72M），同配方同尺，检验"头的函数类到底重不重要"——若线性≈32M 头，则 MLP 是装饰、混合结构+h 几何是一切；若线性崩，非线性必要。
- 2026-09-07 **双联终版（job 526516 完成）**：wide **2.002×/0.771 ≈ 原版不加价**（原版 2.048×/0.770）；deep **2.111×/0.761——衰减段实锤"后半程发力"**（agree 差 -3pt→-1pt、dev_nll 差 0.13→0.075），用户的"深头前半程被大 LR 耽误/各头 LR 舒适区不同"假说与数据自洽。**浅层探针中期（145k）**：linear 落后 27pt（0.447）→ 函数类不足判死；shallow1l 落后 ~2.5pt（0.694）——参照 deep 的追赶先例，**按纪律留到衰减尾审判**（当前无槽位压力）。
- **下一步立项（用户设计 2026-09-07，待磋商细节）：三头赛马挂同一基座**——SmolLM2（原生）拖三头：原版 3L-MLP（对照）/ 5L-残差-prenorm / SwiGLU（后两者参数量对齐），**每头独立 LR 日程**；跑前在本地 4060 做 LR 峰值扫描确定各头舒适区。一跑三答：弗兰肯斯坦基线 + 现代化头升级值 + 公平 LR 对照。详见 §5。
- 2026-09-13 **赛马收官（job 543080，43.4h，余弦 per-arm 峰值 1.5e-3/1e-3/7e-4，warmup 4000，228k 步）**——Q2 首个正式判决：终版（SmolLM2 fineweb dev，native PPL 9.54）：**control 2.41×/agree 0.761 / n_eff 75.0；resmlp 1.90×/0.806/87.5；swiglu 1.78×/0.805/88.6**。架构排序：**门控 FFN+pre-norm（密度最佳）≈ 深残差 pre-norm（top-1 最佳）≫ 3L-MLP**。旁证：①余弦全程无平台（各 60k 窗口斜率全正 +0.002~0.005/10k），末 30k 收平——固定预算用余弦的裁定获曲线级证实；②对照臂复现探针轨迹：2.40×@50k 即饱和，228k 仍 2.41×——**32M mlp3 在 SmolLM2 上是容量约束签名**；③早期效率：agree 0.75 里程碑 control 203k / resmlp 59k / swiglu 44k；④生成侧 swiglu 贪心能跟住教师开头若干 token（control 首句即漂移）。三臂终版头已拉回本地（`runs/race3_head_{control,resmlp,swiglu}_final.pt`）。**注意跨模型口径**：SmolLM2 线（V=49152，M=16，native PPL 9.54）与 Llama 线（128256/17/13.09）的 PPL 比不可直接横比。

## 7. 2026-09-19 对打后方向裁定（内部，不进 docs/27）

> 用户裁定，私下记录；对打报告（docs/27）只保留事实测量，战略语言收在这里。

**认输判定**：CFHead-T4（论文命中表原装配置）在**同等带宽预算**（双方 ~95MiB/步：其 INT6 索引图 95.3MiB 理论值 vs 我方 fp16 头 95.0MiB）下，纯 GPU 解码保真度胜过 MoB 头——预算对齐教师强制：k=32 我方赢 EN/ZH +2.5~3.1pt（紧预算下逐位概率排名结构优于 VQ 粗分），k=256 被反超 1~2pt（其粗筛建在真实权重上，容错足够；我方 92% 进度密度在 ~2% 位置给不足质量）。小候选集精度优势的唯一意义场景是"GPU 出候选 + CPU 内存里精确重排"（lm_head 可移出显存，CPU 按需加载权重行重排+取嵌入回填骨干）——但对现代 CPU，32 行 vs 256 行 gather-GEMV 都是毫秒级，**不构成"互有胜负"的主张。是真的被打败了，幅度不大。**

**下一步方向**：端到端蒸馏实验为主线（独立生成的主战场在此，级联只是兼容模式）。若端到端效果一般 → 回头优化 MoB 头训练法（训练侧杠杆已被 docs/27 §2.4 的"精确上限也追不上"所证明），缩小与 CFHead 的差距，走"**既能加速现有模型推理，也具备端到端蒸馏潜力**"的双轨定位。

**解码策略遗产**（有效部分）：scoreflip（宽发严收+精确重打分，尖锐位自截断 90-105 候选）为当前最优便宜提议；bit 级方差序（翻转优先级=翻转位方差和降序=分量内精确似然序）成立；分量级方差序证伪。
