# 25. 高风险撞车分析：HiDRA 与 CFHead（2026-09-18）

> 用户发现两篇高风险撞车论文并提供 PDF（`docs/68_HiDRA_A_Blazing_Fast_LM_Hea.pdf`，7 页；`docs/Fast_LM_Head_via_Coarse-Fine_Decomposition_and_Tile-Wise_Weight_Clustering.pdf`，14 页）。本文件为逐篇精读 + 逐主张撞车判定 + 定位修订 + 应对实验清单。结论先行：
>
> **CFHead（IEEE Trans. Computers 2026 正式录用，代码公开）杀死了"学习式候选提议 + 原头精确重排"的形状唯一性，并部分侵蚀 offload 叙事；HiDRA（ICLR 2026 TTU Workshop，270M 小模型）杀死了"嵌入空间二叉树码"的构造新颖性。两者都动不了三根幸存支柱：归一化替代头密度（无原头可生成）、原生预训练可行性、语义码接口——因为这两篇本质都是"加速器/路由器"，必须保留原 lm_head 在场，而我们是"替代表示"。定位必须彻底从"更快的头"转向"可替代 softmax 头的表示"，级联降格为兼容模式。**

---

## 1. HiDRA 精读（Cactus Compute，ICLR 2026 Test-Time Updates Workshop）

**机制**：把词表排成深度 L≈log2 V 的二叉决策树（Gemma 262k → 深度 18），每个内部节点一个超平面 `bit = 1[hᵀd+b>0]`。树用 **Fisher LDA 方向 + 中位平衡切分**在嵌入矩阵上自顶向下构建（与我们 codebook 的"2-means 方向 + 中位平衡切分"是同一族构造）；决策向量再用 WildChat 教师强制隐状态做 BCE 微调。推理 = 逐层路由（beam routing 保留 top-k 路径）→ 到达深度 l 后**只对子树内 token（V/2^l 个）跑原 LMHead**。复杂度 O(Ld + (V/2^l)d)。层级概率 p(k)=∏ p_l^b(1-p_l)^(1-b) 有定义，但论文自己声明截断分布"perplexity 不可与 baseline 直接比较"。

**结果（Gemma 3 270M-IT，WildChat）**：代表点 l=4, k=4：输出级 CPU 加速 8.04×（15.33→1.91ms），**top-1 掉 4.2 个百分点**（0.7455 vs 0.7875）；端到端 CPU 1.24×。OOD（FineWeb-Edu）保留比例与域内相近。

**质量评估**：Workshop 论文（TTU 是非主会 workshop）；单模型 270M、单域 WildChat、Teacher-forced 评测；保真掉 4.2pt 是其 headline 数字；无密度主张、无生成质量评测、无代码。威胁在**概念优先权**（"嵌入空间上的二叉层级码 + 冻结骨干免重训"已被占位），不在结果强度。

## 2. CFHead 精读（IEEE Trans. Computers 2026，已录用，代码公开 github.com/HigherIdeal/CFHead）

**机制**：**免训练**的粗-细两段式。离线：lm_head 权重按隐维切 tile（如 8），每个 tile 内对 12.8 万个 V 维局部权重向量做 k-means（如 4-64 类）→ 码本（16KiB）+ INT2 索引图（7.84MiB，存储压 63.9×）。在线：隐状态 × 码本生成激活相关 LUT（2KiB），然后**纯加法 LUT 查表 + 归约**为全词表每个 token 算粗分数（消灭乘法）→ top-k（256-8192）候选 → 用**原始 FP16 lm_head 权重**对候选做精确 GEMV 得最终 logits。候选是 **token 级**的（这是它打 FlashHead 的点：簇级掩码会漏 token，它不会）。

**结果**：9 个下游基准 greedy 平均仅 **-0.21%p**（FlashHead -10.3%p、VocabTrim -6.34%p，同表对打全赢）；LM-head 孤立加速 5.82×（最高 12.7×，23 个模型跨 6 家族）；DGX Spark 端到端 TPOT 1.16-1.18×（A100 上 ~1.0×）；greedy 长生成 top-1 命中率 100%（k=256，16k 步）；nucleus 采样 k=256 时 token 级命中 91-97%（分布被静默改变，用 HumanEval+ 不变来辩护）；batch 32 仍 1.7-2.1×。

**质量评估**：正式期刊、实验扎实、直接打败我们此前认定的最强竞品 FlashHead。**这是我们迄今遇到的最强撞车**。它是"候选筛选 + 原头精确重排"赛道的免训练版完全体。

## 3. 逐主张撞车判定

| 我们的主张（docs/18/19） | HiDRA | CFHead | 判定 |
|---|---|---|---|
| 语义二叉树把词表编码进超立方体（码本构造） | **撞**：LDA 方向+中位平衡切分 ≈ 我们 2-means 方向+中位平衡切分，同族构造 | 不撞（它的"码"是 tile 级 VQ 索引，无语义几何） | **构造新颖性死亡**，必须引 HiDRA 并划界（见 §5） |
| 学习式密度提议器 + 原头 gather 精确重排（docs/19 §4"形状文献唯一"） | 部分撞（learned router + 原头子树打分，但子树=16k token，非 gather-32） | **撞死**：免训练粗筛 + 原头精确 GEMV 重排，greedy 100% 保真 | **形状唯一性死亡**；幸存差异 = 候选集小 10-100×（32 vs 256-8192）、概率可校准、可自适应定候选 |
| 候选集内原头精确权重 + 截断采样等价 | 弱撞（无归一化，自己承认 PPL 不可比） | **强撞且更强**：greedy 逐 token 与原头完全一致（100% hit），采样 91-97% 静默近似 | 我们的显式覆盖统计 + 截断等价框架仍成立，但"唯一性"表述作废 |
| lm_head 可常驻 CPU（offload 首次可行，docs/19 §2） | 不撞 | **部分撞**：它的 fine stage 也是小 gather（k=256 → 1MiB/步），原表也可放 CPU/DRAM | 我们 gather 小 8×（131KB vs 1MiB）+ 纯替换模式根本不需要原表；叙事需改为"替换模式零原表"而非"offload 首次可行" |
| 头带宽 −75~86% / CPU 11.3× | 不撞（它还有 16k 子树 GEMV） | **侵蚀**：它每步流量 ~9-40MiB（索引图+候选行）< 我们 MoB 头的 71-123MiB | 作为 wrapper 它每步流量比我们**小**（但需 501MiB 原表在场）；我们只有"无原表模式"才赢带宽账 |
| **归一化全词表密度头（无原头独立生成、PPL 可测）** | 不撞（无密度） | **不撞**（无原头不能工作——fine stage 依赖原 FP16 权重） | **幸存，升为第一支柱** |
| **原生预训练结构可行性（轴 B）** | 不撞 | 不撞 | **幸存** |
| **码即接口（空余顶点/ECC/掩码约束，语义布局）** | 不撞（树只是路由设备，无语义紧凑性概念） | 不撞（索引无语义） | **幸存**；且"语义树 vs 随机码/LDA 树的紧凑性差距"从内部消融升级为**对 HiDRA 的差异化实证** |

## 4. 三流派分野图（定位修订的核心）

| | 需要原 lm_head 在场？ | 有归一化密度？ | 训练成本 | greedy 保真 | 代表作 |
|---|---|---|---|---|---|
| **检索/筛选 wrapper** | 是（候选行 gather） | 无 | **零**（免训练） | ~100%（CFHead）/ 有掉点（FlashHead） | CFHead, FlashHead, HNSW, CSV |
| **层级路由器** | 是（子树 16k token 也要打分） | 无（截断分布） | 低（BCE 微调） | 掉 4.2pt（HiDRA） | HiDRA |
| **替代表示（我们）** | **否（纯 MoB 头可独立生成）** | **有（全词表归一化）** | 中（蒸馏 25 GPU 时） | 级联 93.8-96.5% / 密度 2.0× PPL | **MoB Head** |

**修订后的一句话定位**：
> "CFHead/FlashHead 回答了'怎么更快地算同一个 softmax'，HiDRA 回答了'怎么更快路由到同一个头'——我们回答的是'**这个头本身能不能换成一个更小的、带归一化密度的、可编程码上的表示**'：无原头可生成（2.0× PPL 且未收敛）、可原生预训练（1.89× 判据通过）、码接口可扩展词表/约束解码——三件事没有任何 wrapper 或路由器能做，因为它们在定义上依赖原头在场。"

级联解码在新定位里降格为"**兼容模式**"：当原表可用时提供 93.8-96.5% 的近似无损重排；系统价值锚点转移到纯 MoB 头的独立性与表示层。

## 附录 A：CFHead 指标机制详解（2026-09-18 调查）

**指标定义**：top-1 hit ratio = 原头 argmax ∈ 粗阶段 top-k 候选集 的步占比（**候选集包含率，非重排一致率**；不检查候选集内部排序）。greedy 下 hit=100% ⇔ 逐 token 与原头一致——因为细阶段用原始 FP16 权重对候选算精确 logits，argmax 在候选集内则 argmax 不变，归一化对 argmax 无影响（Table II 16k 步 100% 即此意）。

**greedy 100% vs nucleus ~95% 的四层原因**：①指标语义不同——greedy 匹配 argmax 成员资格（排序性质），nucleus 匹配两次随机抽取的实现（分布性质，概率性）；②**截断**——top-p=0.9 的 ~10% 尾质量在候选集外物理不存在，原头采到尾部必 miss；③**重归一化失真**——候选内 p'(t)=p(t)/mass(C) 系统性上权重；④粗分噪声在 top-p 边界换入/换出支撑集。argmax 对②③④免疫，采样全敏感。**100% 是"排序正确"，95% 是"分布不同"。**

**能否重建原头 top-k 质量分布**：候选集内部逐位精确（细阶段 = 原权重精确 GEMV，若候选 ⊇ 真 top-k 则排名完全一致）；候选集之外**没有任何分数**（非近似差，是缺席）→ 无全词表 PPL、温度/top-p 语义被静默条件化、无尾部密度。与我们级联边界结构相同（docs/09 §6.1），但 MoB 头自身携带全词表归一化密度（12.8 万 token 全有显式概率，尾部 2.0× PPL），CFHead 除 k 候选外无密度。**划界句：CFHead = 精确但不完整（exact-on-support）；MoB = 完整但近似（full-support density）。**

## 附录 B：我们的树/头 vs HiDRA 逐点对照（对照 tools/build_codebook.py、mob/mob_common.py、train/p2_train.py 源码核实）

**树构建**：①几何——我们 L2 归一化到单位球面全程余弦几何；HiDRA 原始欧氏空间 + 显式各向异性建模。②分裂方向——我们 **2-means（余弦）质心差**（3 重启 + 最远点初始化；cone 上裸 2-means 会歪故只取方向不切簇，docs/04 §3.1）；HiDRA **LDA 方向** Σ_w⁻¹(µ_R−µ_L)（白化均值差）。③分裂点——同为中位平衡切分。④**树的角色（本质分野）**——我们的树建完即弃，只留 M=17 位顶点地址（推理时树不存在），HiDRA 的树就是推理计算图（每个内部节点每 token 执行一次）。⑤空余顶点——我们有 2816 个（Hamming 回退/扩展语义），它的 262144=2¹⁸ 恰好无空余。⑥质量验证——我们有语义紧凑性实测（Hamming-余弦相关 + NN 距离 vs 随机对照），它只有路由准确率。

**输出头与损失**：①头结构——我们 3 层 SiLU MLP（宽 1.2h）→ K×17 位 logits + K π logits；HiDRA 每节点一个线性二分类器（18 点积，无隐藏层）。②输出对象——我们输出归一化混合密度 p(y)=Σ_k π_k ∏_m Ber(y_m;σ(z_km)) 覆盖全部 2¹⁷ 顶点（每 token 显式概率）；HiDRA 的层级乘积虽是合法分布但**推理时不从它生成**，只用于 beam 路径排序，真正打分靠原头打 16k 子树。③损失——我们**精确教师加权 NLL**（top-1024 软标签全贡献梯度 + π 熵正则 + DAEM 2→1，分布匹配蒸馏）；HiDRA **每节点 BCE 硬标签**（真实 token 的路由位，无教师分布、无密度匹配）。④**多峰建模（其结构性弱点）**——HiDRA 单 sigmoid/节点在"下一 token 分布跨两子树双峰"时只能抹平边缘概率，**是 Oda 2017"裸伯努利脆弱"的同款结构**，靠 beam routing 打补丁；我们的 K=32 混合在密度层面解决多峰（教师 top-40 仅 ~78% 质量，多峰是常态）。⑤误差行为——我们分量可对冲（roundflip/adaptive 吃的就是这个结构）；它硬路径逐层 commit，18 层误差乘法累积，漏一个超平面进错子树。

## 附录 C：CFHead 评测协议疑点——缺失测试集单步指标（2026-09-18 深挖，用户发现）

**事实**：全文检索 teacher-forced / held-out / dev / perplexity 评测语境零命中。top-1 数字全部出自：①Fig 5+Table XI/XII 单 prompt（"How to learn LLM?"）greedy 256 步，且用 cluster=256 特大码本（与运行时 cluster 4/64 口径不一致）；②Table II ShareGPT/LMSYS/LongBench 取 prompt **自由生成** 8k/16k 步；③Tables III/IV nucleus 实现匹配率（256 步×30 样本，唯一数据集输入的保真数字，91-97%）；④Fig 6/Table VI 下游任务准确率。**从未报告 held-out 测试集上 teacher-forced 单步 top-1 一致率（无论粗筛自身还是细阶段后）——基础指标缺失。**

**三个疑点**：①**重复回路混杂**——1B/8B 级 greedy 长生成几乎必然滑入复读循环（论文 §II-A 自引三篇 repetition penalty 文献，不可能不知情），复读段 argmax 平凡可预测、候选包含自动成立，16k 步轨迹可能 90%+ 步处于平凡段，"100.0%"可被复读段灌出；论文无位置分桶/非复读子集/teacher-forced 对照，混杂无法排除；且全部 24 格精确 100.0%，自由生成前几百步自然前缀上一步不丢反而需要解释。②**轨迹漂移**——自生成轨迹一旦 miss 即偏离自然分布，后续包含率测于 CFHead 自选上下文（温和自证循环）。③**指标弱+预算大**——"原 argmax ∈ 粗筛 top-256"是包含率非一致率，候选预算 8× 于我们（我们 32 候选重排一致率 93.8-96.5%、hit@top8 99.9%）；此弱指标在自然文本上本应 ≈99-100%，把它当 headline 而从不报强指标才是问题。

## 附录 D：内部矛盾与口径迷宫（2026-09-18 深挖 round 2，用户悖论推动）
