# 编码器 MLP 实验（负结果，已终止）

日期：2026-09-01 · 状态：**终止（用户拍板）** · 结论：17 位码 → 嵌入向量的 MLP 查表替代不可行

## 1. 任务设定（用户提议）

训练编码 MLP：二进制码（17 位）→ 词嵌入向量（2048 维），MSE 监督，训到过拟合（该映射本质是固定查表，128256 对输入输出）。若成，则嵌入层词表矩阵可被网络替代，与 MoB 解码头构成"码→MLP→骨干→MoB→码"的全对称闭环。

## 2. 两次运行（`scripts/train_encoder.py`）

| 配置 | 参数量 | 结果 |
|---|---|---|
| width 3072 × 3 层（复用解码器尺寸），6000 步 | 25.2M | rel_mse 平台化 0.86；余弦相似度 mean 0.375 / median 0.379 / p1 0.169；**插件 PPL 测试：原表 55.6 vs MLP 100,679（劣化 1810×）——决定性失败** |
| width 8192 × 3 层（用户指示优先加宽），4000 步 | 151.2M | step 1000 处 rel_mse 0.8678——与窄版**同一平台**，宽度无效；且此宽度下 MLP 体积（576MiB fp32 / 288MiB fp16）已不低于 bf16 词表矩阵（501MiB），压缩卖点同时消失。用户据此叫停。 |

## 3. 失败分析

- **信息论层面**：嵌入表是 262.7M 个自由标量；即便宽版也只有 151M 参数（1.7 标量/参数）。纯记忆型压缩在该比例下不可行。
- **结构层面**：从 17 位码出发，可学的只是"子树平均方向"级别的结构（余弦 ~0.38 ≈ 捕捉语义邻域的粗方向）；子树内部的逐 token 嵌入变化相对码是任意的，不可学。
- **收敛形态**：两次运行均平滑收敛后平台化——是容量/结构瓶颈，不是优化失败。

## 4. 结论（用户 2026-09-01 拍板）

编码器路线终止。编码侧不占显存在工业界已有成熟方案（嵌入表驻留内存、按需流向显存的 offloading），本项目的价值集中在**解码器侧**（消除 h×V matmul 与 V 维 softmax 的带宽/计算瓶颈，见 docs/08 的实测收益）。资源全部回到解码器主线（集群 B+A 长训，job 519759）。
