## 4. 生成样本评估（`runs/p2_final_eval/generations.txt`）

- **贪心（argmax π + 逐位取整）：明显最好**——全部 4 条语法通顺、用词真实、与 prompt 主题贴合，约 8–15 token 后开始语义漂移或重复循环（如 "The dog ran to the park and began to dance. It was a great day for the dog."；又如胖青年 "so medium that he could not fly" 的排比漂移）。
- **τ=0.7 / τ=1.0 采样：显著退化**——从弥散的学生分布中采样放大了逐位噪声，出现拼写碎块（"wze", "unresefined"）。采样模式在当前训练度下不可用。
- 对照：教师贪心全程连贯（同 prompt）。

解读：头部质量集中时（贪心路径）已能产出**语法正确的短句**，里程碑的语义门槛差在"长程连贯"；每 token 有 ~46% 概率偏离教师选择，自回归下误差复利。

## 5. 差距诊断（为什么差 2.13×）

- **a. 学生容量**：18.5M 参数、K=32 分量 vs 教师 2048→128256 的 logits 映射；BabyLM 上教师分布高度弥散（top-1 均值仅 34%），建模全部分布质量对小组分混合是硬任务。
- **b. 训练量**：仅 10M×3（45M token-遍），曲线尚未完全平坦，但趋缓。
- **c. 曝光偏差**：eval 用教师强制的历史；自回归生成用自己的输出当历史，错误复利——生成质量比单点一致率（0.54）看起来更差的主因。
- **d. top-k 截断与尾部**：k=1024 已覆盖 ~95%，残余 ~5% 尾部质量学生从未见过，系统性贡献 PPL 差距的小部分。

## 8. 差距分解分析（2026-09-01，`scripts/analyze_gap.py`，16,384 dev 位置，`runs/gap_analysis.json`）

**关键发现：median gap = 0.011 nats。** 典型位置（教师确信、真值在 rank 1-10）上学生与原头几乎无差；0.76 nats 的均值差距由厚尾贡献。PPL=exp(mean NLL) 对最坏位置极其敏感，2.13× 高估了学生在典型位置上的差距。

按真值在教师分布中的排名分桶：

| 桶 | 位置占比 | mean gap (nats) | gap 份额 |
|---|---|---|---|
| rank 1 | 38.3% | 0.39 | 19.6% |
| rank 2-10 | 27.0% | 0.51 | 18.0% |
| rank 11-40 | 10.7% | 1.00 | 14.1% |
| rank 41-1024 | 13.4% | 1.47 | 25.9% |
| rank >1024 | 10.6% | 1.62 | 22.4% |

按教师熵分位：Q1(<3.82) gap 0.42 / Q2 0.74 / Q3 0.91 / Q4(>6.28) 0.98；熵最高的两半位置贡献 62% 的总差距。

**含义**：差距的重心在**教师本身就弥散的多峰位置**（rank>40 的 24% 位置贡献 48% 差距；高熵两半贡献 62%）——正是 K=32 分量混合表达力最吃紧的地方。这支持选项 **B（加大容量）** 作为主杠杆；选项 A（更多数据）为辅助。另据 median≈0 可修正叙事：在教师确信的位置上学生已达 exp(0.39)≈1.5× 的接近度，后续报告可补充 rank-1 受限 PPL 作为第二口径。

## 11. 大头稳定性验证（K=128, width 3072，本地，1024 步）

**结论：通过，且收益超预期。** 与 K=32 的 P1.5b 探针同规模（1024 步 / 4.1M tokens）直接对照：

| 头 | dev top-1 一致率 | dev NLL | 有效分量 | 死分量 |
|---|---|---|---|---|
| K=32, width 2458 | 0.502 | 5.17 | 23.4 / 32 | 0 |
| **K=128, width 3072** | **0.687** | **4.74** | **73.9 / 128** | **0** |

- 稳定性配方（k-means 顶点 init + π 熵正则 + DAEM）在 4× 分量数下依然成立：零死分量、无 NaN、显存 7.87GB 在 8GB 预算内（`--loss-chunk 1024`）。
- **容量确实是 P2 差距的主要约束**：同步数同数据量下一致率 +18.5 个点。对 B+A 集群跑的信号非常正面。
- 注意：n_eff=73.9/128 意味着约 42% 分量近乎闲置——k-means 顶点初始化保活了它们（无死分量），但 K=128 可能仍偏多；集群跑可考虑 K=64 或加观测再定，留给用户裁决。
- 产物：`runs/p3_k128_stab/head_final.pt`（129MB，~32M 参数头）。
