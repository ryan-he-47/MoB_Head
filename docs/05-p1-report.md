# P1 报告：MoB 蒸馏管线冒烟测试（本地，过拟合 8k 位置）

日期：2026-08-31 · 状态：**P1 通过** → 进入 P2（V100 全量蒸馏）准备

## 1. 测试设置（`scripts/p1_smoke.py`，按 docs/03 §4.2–4.5 实现）

- 冻结骨干抽取：16 chunks × 512（BabyLM-10M 前 300 行/文件）→ 8176 个位置；每位置教师 top-1024（重新归一化，权重和 = 1.0000 已校验）。
- MoB 头：3×2458 MLP（SiLU）+ 576 输出（32×17 bit-logits + 32 π-logits），~18.5M 参数，全 fp32。
- 损失：精确加权 NLL，logsigmoid 逐位 + logsumexp 混合，fp32，损失按 2048 位置分块。
- 稳定性配方：k-means 顶点初始化（bit-logits ±4，经输出层 bias 注入）；π 熵正则 λ=0.01；DAEM 温度 2→1（前 10% 步）；grad clip 1.0。
- AdamW lr=2e-3，2000 步全批量，RTX 4060 本地，~12 分钟。

## 2. 结果

| 指标 | 值 | 判读 |
|---|---|---|
| 加权 NLL | 10.24 → **3.86 nats**（均匀顶点基线 11.79） | 单调收敛，无 NaN/尖峰/爆炸 |
| 有效分量数 exp(H(π̄)) | **27.6 / 32** | 无模态坍塌 |
| 死分量（π̄<1e-4） | **0** | 初始化+熵正则生效 |
| 解码 == 教师 top-1（argmax π + 逐位取整） | **72.8%** | 管线级成功（过拟合集上） |
| 混合分布在教师 top-1 码上的概率 | 0.339 | ≈教师 top-1 平均质量 0.343 —— 标定一致 |

注：3.86 nats 已接近目标分布自身熵的下限（教师 top-1024 分布在这些位置上相当弥散，top-1 均值仅 34%），即交叉熵 ≈ 熵，说明头在过拟合集上几乎完整复现了教师 top-k 分布。

## 3. 生成观察（非里程碑口径）

过拟合头在未见过的新 prompt 上做贪心自回归：输出退化（如 `... to cINFy it. demand to be attempt...`），教师贪心则流畅。符合预期——8k 位置过拟合的头对 OOD 隐向量没有泛化义务，此读数仅证明"骨干+MoB 头自回归解码链路"机械上可跑通（顶点合法性、token 映射、逐位取整均正常）。

## 4. 结论与下一步

- **管线端到端验证通过**：目标抽取 → 顶点初始化 → 稳定训练（零死分量、零数值事故）→ 解码 → 指标。
- 泛化能力（新位置上解码 == 教师 top-1 的比例、归一化 PPL 差距）只有全量训练后才能回答 → **P2：V100 slurm，BabyLM-10M 全量蒸馏**。
- P2 需要的工程项：生产版训练脚本（全量 13M tokens、按 epoch checkpoint、告警面板、bf16 骨干 + fp32 头、损失分块）、sbatch 提交脚本、以及用户的集群信息（分区名/账户/QoS、提交方式）。

## 5. P1.5 补充：held-out 泛化验证（2026-08-31，本地 4060）

P1 的 72.8% 是在**训练过的位置**上测的，无法暴露目标对齐 off-by-one 类 bug。用生产脚本 `p2_train.py` 做迷你训练（2048 chunks ≈ 1M tokens，256 步，~4 分钟）后在**未见的 babylm_dev 位置**上测：

| 指标 | 干跑（8 步） | P1.5（256 步） |
|---|---|---|
| dev top-1 一致率 | 0.120 | **0.366** |
| dev NLL | 9.99 | 5.43 |
| 有效分量 / 死分量 | 31.5 / 0 | 23.1 / 0 |

**结论：泛化链路健康**——held-out 一致率随训练显著爬升（若是目标错位 bug 会接近 0），无分量坍塌。全量 P2（13M tokens × 3 epochs ≈ 23k 步）预期远高于此。另测算：全量 10M×3 epochs 在本地 4060 上约需 5-6 小时，如集群排队久可本地过夜跑。

**P1.5c：学习曲线探针**（8192 chunks ≈ 4M tokens，1024 步，~18 分钟，本地）——确认曲线形状无早平台化：

| 步数 / 训练量 | dev top-1 一致率 | dev NLL | 有效分量 / 死分量 |
|---|---|---|---|
| 8 步（干跑） | 0.120 | 9.99 | 31.5 / 0 |
| 256 步 / 1M tokens | 0.366 | 5.43 | 23.1 / 0 |
| **1024 步 / 4M tokens** | **0.502** | **5.17** | 23.4 / 0 |

训练 NLL 到 1024 步仍在随 LR 衰减下行（11.8→4.90），一致率近似随 log(步数) 线性增长。**P2 全量（23k 步）按原计划投入的性价比成立，无需调整。**

1024 步头的 p3_eval 对照（16 dev chunks）：native NLL 4.02 / PPL 55.6；MoB NLL 4.87 / PPL 130.8（比值 2.35×，256 步时为 3.19×）；生成样本已出现局部连贯的真实词句（长程仍漂移/循环，符合 4M tokens 训练量预期）。样本与指标落盘 `runs/p1_5b_eval/`（期间修复：Windows GBK 控制台打印非 ASCII 崩溃，p3_eval 已改 stdout UTF-8 + 先写文件后打印）。

**P1.5b：p3_eval 验收管线同步验证通过**（用 P1.5 的欠训练头，8 dev chunks）：native 头 NLL 4.00 / PPL 54.9；MoB 头 NLL 5.16 / PPL 175.0（比值 3.19×，256 步欠训练下的正常差距）；归一化 logZ 通路（对全部 128256 合法顶点求和）计算无误；生成样本落盘正常（欠训练头的 MoB 贪心呈重复循环、τ=0.7 半连贯，符合预期）。此处的意义是**验收脚本本身已端到端验证**，P2 完成后可直接出对比数值。期间修复：cross_entropy target 需 int64（p2_train/p3_eval 的输入 ids 统一改 long）。
