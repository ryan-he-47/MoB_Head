# 实验计划：基于混合伯努利 MDN + 语义二叉树的 LLM 解嵌层蒸馏

日期：2026-08-31 · 状态：**决策已定，进入 P0**（决策记录见 §8）
依据文档：`docs/01-survey-gmm-stability.md`（GMM 数值稳定性，现主要服务于备用方案）、`docs/02-survey-output-layer-prior-art.md`（先验工作与事实核查）

## 1. 一句话方案

冻结 Llama-3.2-1B 骨干，在 BabyLM 2023 语料上把原解嵌层蒸馏为一个 ~18.5M 参数的 MDN 头（3 层 × 1.2h MLP，输出 **32 分量 × 17 位因子化伯努利混合**，Mixture of Bernoullis, MoB）；词表经语义二叉树映射到 17 维超立方体顶点；推理时按分量权重（温度 τ）选分量、逐位取整得到顶点 → token id，完全绕开 h×V matmul 与 V 维 softmax。

**2026-08-31 架构转向（用户拍板）**：主线从球面 GMM 切换为**混合伯努利**；GMM 降为备用/对照方案。转向理由：离散码空间上似然精确（无需噪声连续化）、无 σ 奇异性与 clamp 需求、与二叉树结构天然对齐。

## 2. 可行性评估（结论：可行）

### 2.1 支持点

- **新颖性核实**：三要素（语义位码生成、混合密度头、超立方体语义码）各自有先验工作，组合未见（docs/02 §5）。最近邻：ECOC-NSP 2019（语义序位码 + 逐位伯努利，但非极小码、非混合、从头训练）、Kumar & Tsvetkov 2019（球面密度，单模态）。
- **MoB 与语义树互补**：覆盖一个子树的分量 = 共享前缀位高置信 + 变化后缀位 p≈0.5，因子化伯努利对此表达**精确无近似**；逐位独立假设的短板主要由树布局 + 32 分量混合吸收。纠错码（ECC）作为第二位翻转对策的分析见 §4.6。
- **验收指标严格可算且便宜**：p(t) = Σ_k π_k · Π_j Bern(c_tj; θ_kj)，分母对全部合法顶点精确求和（V×K×M 次运算，仅评测时付出）→ MDN 头归一化 PPL 与原头 PPL 直接可比。
- **解码开销**：选分量 O(K) + 逐位取整 O(M) + 合法性校验 O(1)（顶点恰为合法码字则无需搜索；仅当取整落到 2816 个空余顶点时才需在最近合法顶点中小范围搜索）。

### 2.2 必须正视的两点

- **参数账**：Llama-3.2-1B 已核实 `tie_word_embeddings=true`，词表矩阵被输入嵌入共享——本项目对该模型的收益是**推理计算与带宽**（h×V matmul + V-softmax → 0），不是参数量。若要"参数也省"的叙事需非 tying 目标模型。默认不影响推进，如需调整目标模型请用户裁决。
- **top-40 截断**：教师分布 top-40 以外的质量被丢弃，覆盖率必须在 P1 实测并记录；不足则升 top-k 或加质量校正。

### 2.3 算力核算

- 骨干 bf16 权重 2.47GB；冻结前向，本地 RTX 4060 8GB 可跑小批量冒烟（教师 logits 按序列分块提取 top-40，不实体化 B×T×V）。
- MDN 头 ~18.5M 参数（见 §4.2），训练负载极小；V100 32GB 充裕。
- BabyLM 10M 词 ≈ 13M tokens（Llama BPE），骨干前向一遍分钟级；全量蒸馏在 V100 上以小时计。

## 4. 架构与训练规格

### 4.1 码本构建（语义二叉树）
- 取嵌入表 E（128256×2048，tied），L2 归一化；递归二分：每层对当前簇做 2-means（cosine），左 0 右 1，共 17 层 → code ∈ {0,1}^17。
- 簇大小 < 2 时提前终止，剩余位补 0 并记录。
- 产物：`codebook uint8[128256, 17]`、合法顶点掩码 `valid[131072]`、树结构（供分析）。
- 校验：随机抽 1000 对 token，语义近邻对的 Hamming 距离应显著小于随机对（对照随机码本）。

### 4.2 MDN 头（MoB 主线）
- 输入：骨干最终 RMSNorm 之后的 h（即 lm_head 的原输入），2048 维。
- MLP：2048 → 2458 → 2458 → 2458（1.2h），SiLU。
- 输出头：2458 → **576 = 32 ×（17 bit-logits）+ 32（π-logits）**。
- 参数化：逐位概率 θ_kj = sigmoid(z_kj)；π = softmax(π-logits / T_daem)。无 μ/σ/噪声。
- 参数量：主干三层 ≈ 5.03M + 6.04M + 6.04M，输出头 2458×576 ≈ 1.42M，合计 ≈ 18.5M。

### 4.3 蒸馏目标（已定：精确加权期望）
- 教师：冻结骨干对 BabyLM 文本前向，每位置取 top-40（token id + 概率，重新归一化），序列分块计算避免实体化全 logits。
- 损失：**L = −Σ_{t∈top40} p_t · log [ Σ_k π_k · Π_j Bern(c_tj; θ_kj) ]**，无采样噪声、无连续化噪声。
- 逐位 log 概率用 logsigmoid 形式计算（数值稳定标准写法），混合用 logsumexp，全程 fp32。

### 4.4 训练稳定性配方（MoB 版；GMM 特有配方退役）
MoB 无 σ 奇异性、无 clamp 需求，剩余风险是**分量权重萎缩/模态坍塌**（与 GMM 同源的混合竞争动力学）：
1. 初始化：分量 bit-logits = ±c（c≈4）按活跃顶点集 k-means 中心的位模式注入；π 均匀（CSI 2024 教训：随机初始化 + 高估 K 必坍塌）。
2. π 熵正则：+λ·Σ_k π_k log π_k（Zhou et al. 2020），λ 从 ~0.01×NLL 量级起步调。
3. DAEM 退火：π logits 温度 2 → 1，前 10% 训练步线性退火（Ueda & Nakano 1998）。
4. 损失全程 fp32 + logsumexp，置于 autocast 之外；梯度 clip = 1.0 兜底。
5. **监控告警**：有效分量数 exp(H(π))；死分量（责任质量 < 1e-4）计数；分量内逐位熵直方图（健康分量应大部分位低熵）；分量均值（按位概率）到最近合法顶点的距离分布。

### 4.5 解码
- k ~ softmax(π-logits / τ) 选分量 → 逐位取整 round(θ_kj) → 顶点。
- 顶点合法（掩码命中）→ 直接映射 token id；落在空余顶点（概率应极低）→ 在 Hamming-1 邻域找最近合法顶点。
- 多样性选项：逐位采样 bit ~ Bern(θ_kj) 代替取整（默认取整，采样作为生成多样性消融）。
- τ ∈ {0.7, 1.0} 扫描用于生成里程碑。

### 4.6 ECC（纠错码）分析——**建议主线不加，P4 消融验证**（待用户确认）
用户提议为二进制码加海明码等纠错码以纠位翻转。分析：
- **它解决的不是独立假设**：逐位独立假设的建模短板由语义树 + 混合吸收（§2.1）；ECC 解决的是解码端位翻转容错。
- **可行性**：Hamming SECDED 对 17 个数据位需 5 个校验位 → 22 位码，min 距离 3。可行做法：先在 17 位空间建语义树，再拼接确定性校验位；近邻码字统一从距离 1 放大到 3，近邻关系保持，且获得纠 1 位错能力。
- **成本与疑点**：M 从 17 涨至 22（头输出 +32×5=160 维）；码空间稀疏化 32 倍；MoB 逐位取整时高置信位翻转概率本来就低，而"某 bit ≈0.5 取错"的情形 ECC 纠错方向未必指向正确语义——收益不确定。
- **结论**：主线保持 17 位纯树码；ECC 作为 P4 消融项（若届时解码错误集中于单 bit 翻转则启用）。

### 4.7 备用方案：球面 GMM 头
若 MoB 训练出现意外（理论上不应），回退到 GMM 方案：32 分量 17 维球面 GMM + 噪声连续化（σ_n=0.2），稳定性配方按 docs/01 §6 的 bottom-line recipe（log-σ clamp [log 1e-3, log σ_max]、σ_max=max(0.30,1.2σ_n)、顶点 k-means init、熵正则、DAEM、fp32 logsumexp、σ 贴顶告警）。GMM 同时保留为 P4 对照组（MoB vs GMM 直接对比有论文价值）。

## 6. 风险与回退

- **R1 分量坍塌** → 熵正则加强 / DAEM 退火放缓 / 贪心分裂（Vlassis & Likas 2002）。
- **R2 码本语义性不足** → 换谱二分或 ITQ 旋转；以随机码本对照确认树的价值。
- **R3 top-40 覆盖率低** → 升 top-k 或加残差质量校正项。
- **R4 PPL 差距大** → 查分量内位熵直方图（欠分裂特征：大量位卡在 ~0.5 且权重集中）；对应措施：升 K、加强熵正则。
- **R5 MoB 意外失效** → 回退 GMM 方案（§4.7）。

## 7. 验收标准（已定）

babylm_dev 归一化 PPL：MDN 头 vs 原头（同一冻结骨干），差距阈值拿到首批数值后由用户定；加固定 prompt 生成段落的人工语义正确性检查（里程碑事件）。
