# 设计原理与方法论：基于混合伯努利网络与语义二叉树的 LLM 解嵌层蒸馏

日期：2026-09-02 · 读者：后续会话的 agent / 合作者 · 性质：方法论定稿（实验证据以 docs/07、08、09 为准）

## 1. 动机与问题陈述

小语言模型的输出层（解嵌层）在每个前向解码步都要执行 h×V 矩阵乘法并做 V 维 softmax。对 Llama-3.2-1B（V=128256, h=2048）而言，这意味着**每个生成的 token 都要从内存整读一遍 501 MiB（bf16）的词表矩阵**。在带宽受限的端侧设备上，这是比计算更硬的瓶颈。本项目目标：把一个冻结骨干的解嵌层蒸馏成一个紧凑的混合密度网络头，使解码完全绕开 h×V matmul 和 V 维 softmax。

## 2. 核心假设

模型的输入是 V 维正单纯形顶点（one-hot）的序列，输出是"下一个顶点是哪个点"的分布。词表空间本身无语义（顶点等距），语义由嵌入向量和隐向量承载，词表只是索引。从图论视角看，模型学的是顶点间的"语义有向图"。**假设**：只要构造一个结构化、数值范围稳定的替代索引空间，模型就能在该空间中以多值预测的方式近似原语言建模能力。

## 3. 设计总览

```
token id ──码本──> 17 位二进制码 c ∈ {0,1}^17（超立方体顶点）
骨干(冻结) ──> 隐向量 h ∈ R^2048（最终 RMSNorm 之后，即原 lm_head 的输入）
MoB 头: h -> 3 层 MLP(SiLU) -> 128 分量 × 17 位逐位伯努利 logits + 128 个 π logits
蒸馏: 冻结骨干在语料上前向，每位置取教师 top-1024 分布，按概率加权的精确 NLL
解码: 按 π 选分量 -> 逐位取整 -> 顶点 -> token id（落空则取最近合法顶点）
```

## 4. 索引空间构造：语义二叉树码本

- 每个词表 token 映射到 M = ⌈log2 V⌉ = 17 位二进制码，即 17 维单位超立方体的顶点（2^17 = 131072，占用 128256，空余 2816）。
- **语义布局**：相近的顶点语义相近——用模型的 tied 嵌入表构建 M 层语义二叉树，二进制位表示分叉。
- **构建算法（实测修正，重要）**：直接对嵌入做 2-means（cosine）二分在窄锥形 LLM 嵌入上会退化为极度不平衡分裂（每层只剥下离群小簇，85% token 到第 17 层仍未分开）。**现行方法**：2-means 仅用于求分裂方向（两质心之差 w），实际切分是对 x·w 投影做**按秩中位数平衡切分**——每层严格对半，保证树深 ≤17 且所有码字唯一。这与谱哈希（spectral hashing, Weiss et al. 2008）的中位数阈值思想同源。产物：`data/codebook.npz`（codes[128256,17] uint8、vertex_id、valid_vertices 掩码）。
- **验证**（docs/04 §3.2）：教师 top-40 目标集合内的加权平均两两 Hamming 距离 4.16（随机码对照 6.43，随机 token 对照 8.29）；40 个目标收进 ~9 个深度-8 子树。全局最近邻指标弱（7.51/17 vs 随机 8.42）是树结构只保留 17 个全局分裂方向的固有性质，不影响操作性指标。

## 5. 解码头：混合伯努利（MoB）

- **架构**：h(2048) → 3×width MLP（SiLU，与骨干一致）→ 输出 K×17 位 logits + K 个 π logits。K=32/width 2458 ≈ 18.5M 参数；K=128/width 3072 ≈ 32.4M。
- **参数化**：逐位概率 θ_kj = sigmoid(z_kj)；π = softmax(π-logits / T_daem)。无 μ/σ/噪声。
- **为什么从 GMM 换成 MoB（2026-08-31 用户拍板）**：GMM 方案需要对离散顶点加噪声连续化，随之而来的是 σ→0 奇异性、σ 钳制、欠分裂告警等一整套稳定性包袱（调研见 docs/01）。MoB 直接活在离散码空间：似然精确、无奇异性、解码即逐位取整。逐位独立假设的短板由语义树天然化解——覆盖一个子树的分量恰好是"前缀位高置信 + 后缀位 ≈0.5"，因子化伯努利对此表达**零近似**。
- **多值性**：单分量的逐位独立伯努利无法表达多模态，混合可以——32/128 个分量各自近乎一个顶点（或一个子树），π 给相对概率。

## 6. 蒸馏目标

- 教师：冻结骨干前向，每位置取 **top-1024**（k 由用户按实测覆盖率拍板：BabyLM 上 top-40 仅覆盖 ~78% 质量，top-1024 ≈ 95%；实测表见 docs/04 §2），概率在 top-k 内重新归一化。
- 损失：**精确加权期望** L = −Σ_{t∈top-k} p_t · log[Σ_k π_k·Π_j Bern(c_tj; θ_kj)]——无采样、无噪声（用户拍板；优于原设想的 n 次采样）。
- 数值实现：逐位 log 概率用恒等式 log Bern(c;z) = c·z + logsigmoid(−z)（免 exp 溢出），分量混合用 logsumexp，全程 fp32。
- **损失下限**：该损失的理论下限 = 教师 top-k 重归一分布的熵（BabyLM dev ≈ 4.0，FineWeb-Edu dev ≈ 2.5，即 native 头的 NLL）。读数永不归零，接近下限时自然变慢——这是判定"收敛慢是否正常"的第一参照系。

## 7. 训练稳定性配方（MoB 版）

源自 GMM 文献（docs/01）并适配离散混合，全部经本地+集群实测：
1. **k-means 顶点初始化**：分量 bit-logits = ±4 按活跃顶点集 k-means 中心的位模式，经输出层 bias 注入（随机初始化 + 高估的 K 必坍塌，CSI 2024 的教训）。
2. **π 熵正则**：+λ·Σ π log π，λ=0.01（Zhou et al. 2020 的混合权重熵代价思想）。
3. **DAEM 退火**：π logits 温度 2→1，前 10% 训练步线性退火（Ueda & Nakano 1998 确定性退火）。
4. 损失全程 fp32 + logsumexp；grad clip 1.0 兜底。
5. **监控告警**：有效分量数 exp(H(π̄))（健康线 ~>K/2）；死分量（π̄<1e-4）计数；dev 面板（top-1 一致率 + dev NLL）每 1000 步。
6. 日程教训（2026-09-01 实测）：好初始化 + 高熵下限的蒸馏在高 LR 段只有搅动没有进步；WSD（1% warmup + 平台 + 末 35% 线性衰减）+ 峰值 7e-4 的变体在并行对照中前期收敛快一个数量级（见 docs/12）。

## 8. 解码

- 贪心（默认）：k* = argmax π → 逐位取整 round(θ_kj) → 顶点 → token id。
- 采样：k ~ softmax(π-logits/τ)（τ 扫描 {0.7, 1.0}）；逐位可取整（默认）或按 θ 采样（多样性消融项）。
- 落空处理：取整落在 2816 个空余顶点之一（概率极低）→ Hamming 最近合法顶点。
- 开销：选分量 O(K) + 取整 O(M) + 映射 O(1)。实测（docs/08）：头部每步带宽 501→71/123 MiB（−86%/−75%），FLOPs 14×/8× 削减，CPU 单步 11.3× 加速，端到端（4060）+11% tok/s。

## 9. 评测方法论

- **归一化 PPL（验收主指标）**：p(t) = Σ_k π_k·Π_j Bern(c_tj; θ_kj)，分母对全部合法顶点精确求和（V×K×M 运算，仅评测时付出）→ 与原头 PPL 同位置、同骨干、同数据严格可比。
- **top-1 一致率**：学生贪心解码 == 教师 argmax 的位置占比（学习曲线的最灵敏读数）。
- **差距分解**（`scripts/analyze_gap.py`）：按教师熵分位 / 真值排名分桶分解 NLL 差距——P2 的结论"median gap ≈ 0、差距集中在弥散多峰位置"由此而来，是加大容量的依据。
- **生成里程碑**：固定 prompt 的贪心/采样段落，人工判读语义正确性。
- 中途评测：训练期 `--ckpt-every` 的 head_latest.pt 拉回本地跑 p3_eval，得归一化 PPL 的途中读数。

## 10. 开放问题与已决边界

- 在途：B+A 长训（FineWeb-Edu 1B tokens、K=128）余弦版 vs WSD 版的头对头（docs/12 记录）。
- **已实施入主线（2026-09-02）：混合概率全顶点排名解码（mixture-argmax decode）**——对全部合法顶点按 Σ_k π_k·Π_j Bern(c_j;θ_kj) 排名取 top-1，替代"选分量+逐位取整"。实测 +~3 点一致率（0.745 vs 0.717），带宽代价仅扫码本 ~0.3MB。实现：`mob_common.decode_mixture_argmax` / `mixture_vertex_logprob`；`p3_eval.py --decode mixture`（默认仍 round 以保证与已跑完头对头可比）。
- **已入主线（2026-09-02 用户拍板）：级联重排解码（DeepSeek 建议）**——MoB top-32 提议 + 嵌入表 32 行精确重排，top-1 保真 92.2%（上限=召回 93.9%）。实现：`mob_common.decode_rerank_native`，提议侧走 `mixture_topk` 的界剪枝精确排名（与全排名逐位相同）。开销实测（docs/08 §5）：GPU +0.6ms/步（与原生头单步持平），CPU +21.8ms/步（整步 27.6ms 仍 1.5× 快于原生头 41.2ms）。边界：变级联系统、漏召 ~6% 锁死上限、采样分布近似、给不出全分布 PPL（PPL 仍由混合 NLL 承担）。实测与分析：docs/09 §6.1。
- 已否决：ECC 纠错码（主线不加，留消融；分析见 docs/03 §4.6）；GMM 主线（降为对照）；编码器 MLP 替代嵌入表（信息论+结构双重不可行，docs/10）。
- 已知限制：tied 嵌入模型上本项目收益是计算/带宽而非参数量；教师分布弥散语料上 top-k 截断的残余偏差；采样模式（τ=1.0）在当前训练度下不可用。
