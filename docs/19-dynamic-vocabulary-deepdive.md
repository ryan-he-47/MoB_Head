# 19. 深挖补遗：候选-重排范式、密度采样、CPU offload 与 BitLM 的四点反诉判读

> 归档说明：本补充由独立学术评估会话（deepseek-v4-pro + 3 路 librarian + 精读两篇竞品原文）于 2026-09-07 完成，是对 `docs/18-academic-positioning.md` 的深化。用户提出四点"据我所知是全新"的优势，要求验证相关文献能否做到。逐点结论：**四点优势全部成立，但各自需要精确的机制级表述与先例划界**（尤其第 4 点把项目从"输出头替换"赛道正确迁入"运行时动态词表/候选-重排"赛道，这是此前报告漏掉的关键定位修正）。

---

## 0. 核心定位修正（用户第 4 点，最重要的 meta 发现）

主线级联解码（MoB 头提议 top-32 候选 → 原头 gather 32 行精确重排）**并未替换输出层**——小网络只是一个**候选提议器**。因此项目同时属于两条赛道，必须分别对比：

- **赛道 A（输出头替换）**：FlashHead / HNSW-MIPS / CSV-Decode / VQ-Logits / BitLM —— 这是 docs/18 已覆盖的。
- **赛道 B（运行时动态词表 / 候选集收窄 / learned candidate proposal）**：这才是主线真正所在的赛道，docs/18 **未覆盖**，本补充补上。

**赛道 B 的关键结论**：现有"动态词表"工作的候选来源全是**静态结构**（离线聚类 / ANN 索引 / 几何上界 / 语法掩码），**没有任何一个用"在冻结骨干上蒸馏出来的、按概率密度排名的学习式小网络"来逐位置生成候选集**。唯一形状最接近的是 **S2T (arXiv:2604.26940)**——小模型提议 top-K、大模型用自身条件概率精确重排，但它是跨模型协作（SLM 提议 + 另一 LLM 重排），非"同模型冻结骨干 + 蒸馏小头"。

## 1. 第一点：候选集上精确原头权重 + 截断采样等价 + 温度采样 + 检索级速度

**结论：成立，且是四点中最强的差异化支柱。** 逐方法验证"归一化密度 / 温度采样 / 亚-V 每步成本"三要素：

| 方法 | 归一化密度？ | 温度采样？ | 每步成本 | 校准性质 |
|---|---|---|---|---|
| **本项目·混合头** | ✔ 全词表归一化（精确求和，PPL 口径）但**尾部粗**（2.05× PPL，仅 top-1024 蒸馏） | ✔（分量温度 + 逐位） | 亚-V（码本扫描 0.3MB） | 头部密度拟合教师但尾部校准弱——**不进入采样主张** |
| **本项目·级联（主线）** | ⚠ **top-K 密度**（候选集上的精确条件分布，非全词表） | ✔（候选内 = 原头精确 logits × 1/T，逐点精确） | 亚-V（32 行 gather） | 候选权重 = 原头精确 logits 重归一化；32 候选覆盖原生质量 80.3%、native top-8 命中 99.9% ⇒ **截断采样口径（top-40/60、top-p）下与原生采样等价** |
| FlashHead (2603.14591) | ✘ 两阶段近似分布 | ⚠ 启发式（簇 softmax × 簇内 softmax） | 亚-V（p·b 探针） | **未校准**：支撑仅限探测簇（8k/128k token），未探测簇零质量；HellaSwag 概率任务需**蒙特卡洛估计边缘分布**——恰证明无精确全词表密度 |
| CSV-Decode (2511.21702) | ⚠ ε-认证 TV 有界近似 | ⚠ 子词表内可采样 + 残差回退 | 亚-V（稀疏 GEMV） | **最接近"有保证的近似密度"**，但候选源是静态簇 + 几何上界，非学习式 |
| HNSW-MIPS (2608.27460) | ✘ 仅 top-k 检索 | ✘ | 亚-V | 无归一化、无采样 |
| kNN-LM (1911.00172) | ✔（但靠 base LM 保住全 V 支撑） | ✔（τ 调参，启发式） | **超-V**（全 V 头 + 检索） | 插值，检索分布校准差（生成质量论文实证） |
| VQ-Logits (2505.10202) | ✔（scatter+softmax 全 V） | ✔ | 亚-V matvec | **粗粒**：同 codebook 项 token 共享 logit，PPL +4% |
| Mixture of Softmaxes (1711.03953) | ✔（凸组合） | ✔ | **K×V（更贵）** | 精确但成本反向 |
| Sigsoftmax (1805.10829) | ✘（多标签逐维） | ✘ | V 维 | 无配分函数 |
| vMF 头 (1812.04616) | ✘（嵌入球面密度，非词表分布） | ⚠（方向采样→NN 映射） | 亚-V matvec + NN 搜索 | **贪心 NN 解码，多样性差**（GIVT 明言："usually greedy, no diverse samples"） |
| GIVT (2312.02116) / TarFlowLM (2507.00425) | ✘（连续 latent 密度，非离散词表） | ⚠（方差缩放） | TarFlowLM 解码 O(V·d) | 连续域，非词表概率 |
| SCONES (2205.00704) | ✘（V 个独立 sigmoid，未归一） | ✘ | V 维 | 生成需束搜索补丁 |
| 分层 softmax (Morin-Bengio 2005) | ✔（乘积分解） | ⚠ 每节点 T ≠ 全局 T 缩放 | O(log V) | 从零重训，非蒸馏 drop-in |
| 自适应 softmax (Grave 2017) | ✔ | ⚠ 同上 | 亚-V（GPU 不友好） | 从零重训 |

**判读（按用户修正口径 2026-09-07）**：主线级联**不声称全词表密度**——它给出的是"候选集上的精确条件密度"：候选 token 的权重是**原头 gather 出的精确 logits**（温度缩放逐点精确），配合候选集对原生质量的覆盖（80.3% @ 32 候选、native top-8 命中 99.9%），在常规截断采样口径（top-40/60、top-p）下与原生分布**采样等价**（差异仅在被丢弃的长尾，而长尾在截断采样中本来就被丢弃）。因此修正后的第一点主张为：**"候选集内精确原头权重 + 学习式密度驱动候选 + 截断口径下采样等价 + 检索级速度"——这一组合文献未见。** 对比竞品：FlashHead 簇内 logits 虽精确，但**簇级权重 = 质心 logits 的 softmax（近似）**，候选源是静态聚类；CSV 是 ε-近似；两者都没有学习式候选源。分层/自适应 softmax 是归一化 + 亚-V，但是从零重训的静态分解。混合头本身在数学上是全词表归一化密度（PPL 评测口径），尾部仅由 top-1024 蒸馏、校准弱，不作为采样主张的一部分。

## 2. 第二点：嵌入矩阵常驻内存 + CPU 代理 gather/局部 logits + 释放 VRAM

**结论：成立，但定位必须升级——它不是独立的系统 novelty，而是范式 novelty 的价值证明。** 单向因果链：

> 轻量 MDN 头产出小候选集（**范式 novelty**）→ 输出侧从"全 V 矩阵乘"变成"32 行 gather + 局部 logits"（每步 131KB，实测 CPU 步 6.42ms）→ CPU 算 logits 延迟不爆炸 → lm_head 常驻 CPU 的 offload **首次可行** → 省出 (词表矩阵参数量 − MDN 头参数量) 的显存。

链的第一环不存在，整条链就不存在：llama.cpp 已证明"只 offload 不缩候选" = 500ms/token 慢路径（issue #3860）；MNN-LLM 只敢 offload 输入侧（gather 天然小）、把 lm_head 明确留在 DRAM——**因为输出侧从未被变成小 gather，所以输出侧从未有资格 offload**。量化：Llama-3.2-1B 释放 ≈ 501 − 37(K=32) ≈ **464 MiB**（fp16，约全模型 2.47 GB 的 ~19%）；Gemma-2-2B（untied，head 590M×2）释放空间更大。**在论文叙事中，offload 应放在"范式价值验证"章，作为范式 novelty 的直接后果与量化收益，而非并列的系统贡献。**

| 先例 | 出处 | 做了什么 | 与本项目差异 |
|---|---|---|---|
| **MNN-LLM** | arXiv:2506.10443 (2025) | **输入**嵌入表下放 flash，理由与本项目同款（每 token 只触 1/V，Qwen2-7B 仅 7KB/token），省 15% DRAM | **只做了输入侧**；lm_head 仍在 DRAM（输出侧 = 全矩阵乘）。本项目把**输出侧也变成小 gather**，这是 MNN-LLM 没做到的 |
| KTransformers | SOSP 2025 | MoE 模型嵌入表放 CPU（算术强度低），lm_head 放 GPU | 输入嵌入放 CPU 已成熟；lm_head 被当作需 GPU 的计算 |
| vLLM cpu-offload-params | vLLM PR #53120/#53981 | 支持 `embed_tokens`/`lm_head` 选择器 + UVA，offload 1.24GB 嵌入 → +58.8% KV 容量 | 通用机制，非"候选集 + CPU gather"耦合；lm_head 仍需全量计算 |
| FlexGen (2303.06865) / PowerInfer (2312.12456) / ZeRO-Infinity | — | 逐层/逐神经元均匀 offload，**无词表特例** | 通用 offload，不利用候选集 |
| llama.cpp | — | 部分 offload 时 lm_head 天然留在 CPU → **全 V 维 GEMV 在 CPU = 慢路径**（issue #3860: 500ms/token） | 反证：只把 lm_head 丢 CPU 而不缩候选集，就是灾难 |
| LLM in a Flash | 2312.11514 (Apple) | 嵌入表常驻 DRAM（选择性持久化） | Apple 内存侧先例 |
| Apple AFM-on-device | 2407.21075 | 共享嵌入 8-bit 逐通道量化（ANE 特殊处理） | 精度换内存，非 offload |
| HNSW-MIPS 头 | 2608.27460 | 全 CPU 推理 + ANN 候选检索，**矩阵+索引共存**（+5-10% 静态开销） | 无 GPU/VRAM 协同；提议器是静态 ANN 索引非学习头；无"释放 VRAM"叙事 |
| T-MAC (2407.00088) / LUT-GEMM (2206.09557) | — | CPU LUT 微 GEMM 机器（T-MAC 端侧 CPU 反超 NPU） | 提供"CPU 小矩阵乘很便宜"的工程基础 |
| NEO (MLSys 2025) | — | 每 token 小传输可被 GPU 计算隐藏（5-10×），PCIe ~12.5-32 GB/s | 小步传输成本证据 |

**判读**：第二点的真正新颖在于**"输出侧嵌入矩阵也可 CPU 常驻 + CPU 服务"**——因为级联把输出侧从"全 V 矩阵乘"变成了"32 行 gather + 局部 logits"。输入侧嵌入 gather 本就极小（tied 模型每 token 触一行），历史先例（MNN-LLM/KTransformers/vLLM）已证明输入侧可行；但**输出侧**从未有人做成小 gather（MNN-LLM 明确把 lm_head 留 DRAM、llama.cpp 证明丢 CPU 就慢 500ms/token、HNSW 全 CPU 但无 VRAM 释放）。耦合点 = 学习式候选提议器 + CPU 服务嵌入 gather + GPU 只跑骨干，文献未见。**定位（用户定调 2026-09-07）**：此系统 novelty 不是独立贡献，而是**范式 novelty 的价值证明**——正是"MDN 头 → 小候选集"使 offload 首次可行；"省出 (词表矩阵 − MDN 头) 显存"是范式改变的可量化收益，应作为其价值证据呈现。待补：PCIe 输入侧行 gather（每 token B×h 字节）实测成本。

## 3. 第三点：vs BitLM 的"同框架现有模型加速/瘦身"优势

**结论：成立。** BitLM (arXiv:2605.11577) 是**端到端从零的新架构**（块因果骨干 + 扩散头），：
- 训练：无冻结骨干、无蒸馏路径；
- 码：整数码 bin_B(token id)，**无语义布局**；
- 头：扩散逐位去噪，**无归一化密度**；
- 目标：块内**多 token 并行**（throughput），非单 token 分布。

**因此 BitLM 不具备"在同一二进制码框架下、对现有预训练模型做加速/瘦身"的能力**——它必须整体重训，且是"新模型"，不是"现有模型的 drop-in 加速器"。本项目（冻结骨干 + 蒸馏小头，级联重排复用原头）是唯一在"二进制码 + 现有模型加速"交点上工作的方法。这一条可直接写入 intro 划界。

## 4. 第四点：运行时动态词表 / 候选-重排赛道的完整 related work

**结论：候选源全是静态结构，无"学习式密度排名提议器 + 同模型原头精确重排"。**

## 5. 综合：四点反诉后的 novelty 支柱（更新版）

1. **候选集精确权重 + 温度采样 + 检索级速度**（第 1 点，修正口径：候选内原头精确 logits + 学习式候选 + 截断采样等价，非全词表密度）：文献唯一。FlashHead 簇级权重近似、CSV 静态、VQ-Logits 粗粒。最强支柱（且为诚实版本）。
2. **输出侧嵌入 CPU 常驻 + CPU gather**（第 2 点）：**范式 novelty 的价值证明，非独立贡献**——没有小候选集，offload lm_head 就是 llama.cpp 500ms 慢路径；有候选集后 CPU 步仅 6.42ms，省出 (V×h − MDN) ≈ 464 MiB（Llama-3.2-1B）。输入侧有先例（MNN-LLM），输出侧无；需补 PCIe 输入侧 gather 实测。
3. **同框架现有模型加速**（第 3 点）：BitLM 无此能力，成立。
4. **学习式候选提议器 + 原头精确重排**（第 4 点）：精确形态文献未见，需引 S2T + speculative decoding 划界。

**一句话定位更新**（在 docs/18 §8 基础上）：
> "一个蒸馏出的、按归一化混合伯努利密度对语义二进制码排名的**候选提议器**，配合原解嵌头对极小候选集的**精确重排**——在保持温度采样与截断采样等价的同时，让输出侧嵌入矩阵可 CPU 常驻（释放 VRAM），并保持对现有冻结模型的 drop-in 加速能力。这是'运行时动态词表'赛道里第一个学习式提议器，也是'二进制码语言模型'方向里唯一能加速既有模型的框架。"

**两轴合看（用户定调 2026-09-07）**：本范式有两条验证轴——轴 A 推理侧优化（本补充的主战场）与轴 B 原生预训练（docs/18 §1 D3：从零 twin 1.89×，可行性成立、scaling 折扣未探明）。轴 B 是轴 A 的 strong self-consistency 证据：同一套表示既能挂在冻结教师上做近似无损加速，又能独立预训练。**学术价值必须两轴合看**——轴 A 单看撞检索式免训练头（FlashHead/HNSW/CSV），轴 B 单看撞 BitLM，合看才是完整的范式主张。早期阶段事实如实呈现：轴 B 仅可行性验证，折扣上界未探明，不排除更优 trade-off。
