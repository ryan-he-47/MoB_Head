# 14. 续训摸顶 + 解冻骨干微调（新头顶班原生头）方案

> 状态：**待用户拍板**（2026-09-03 起草）。两步计划：① 小学习率续训 WSD 终版头，探头的容量上限；② 头收敛后解冻骨干部分层/LoRA，让 MoB 头直接顶替原生解嵌层在 FineWeb 上微调。等待续训期间先在本地用现头做可行性试水。

## 1. 背景与目标

- WSD 终版（job 520825）：归一化 PPL 2.05×、agree 0.770（round），曲线收尾仍在爬（+0.4pt/万步）——**训练未到顶**（docs/09 §6）。
- 级联解码已达标（有效保真 ~94%），密度侧差距是训练侧 frontier。
- 续训的边际收益有三个来源：余量曲线、第二个 epoch 的数据复扫、更低 LR 的精细收敛。
- 解冻微调是更激进的问题：MoB-NLL（-log Σ_k π_k·Π_j Bern(c_j)，码↔token 双射 + 合法顶点归一化）本身是一个**合法的 LM 训练目标**——不依赖教师分布。若骨干能顺着这个目标共适应（co-adapt），新头就真能"顶班"原生解嵌层，而不只是蒸馏模仿。

## 2. Step 1：续训方案（零新代码，只改参数）

机制已验证：`p2_train.py --resume <weights-only.pt>` 走"仅权重加载 + 新优化器 + 新日程"分支（k-means 初始化只在无 resume 时执行，不会覆盖）。

| 参数 | 续训值 | 说明 |
|---|---|---|
| `--resume` | `runs/p2_fineweb_wsd/head_final.pt` | 仅权重 |
| `--lr` | **2e-4**（待拍板，见 §5-Q1） | ≈ WSD 衰减段收益区的量级；全程 cosine 衰减到 ~0 |
| `--schedule` | cosine | 续跑即抛光，直接衰减 |
| `--epochs` | 1（=245k 步，~24.5h on V100） | 第二遍数据 |
| `--seed` | 换一个 | 重洗数据顺序 |
| `--daem-t0` | 1.0 | 不再退火，T=1 全程 |
| 其余 | 同 WSD 跑（K=128/width 3072/topk 1024/fp16 backbone） | |

- 数据决策点（§5-Q2）：同 1B token 缓存重洗（零成本）vs 新建一份 FineWeb-Edu 1B 缓存（+几小时 CPU 缓存任务，信息全新）。
- 产出验收：跑完自动 p3_eval（同 WSD 跑的 sbatch 链），对照基线 2.05×/0.770。

## 3. Step 2：解冻骨干微调方案（新头顶班）

**目标系统**：backbone（部分可训）+ MoB 头，原生 lm_head 完全不参与前向与损失。

**损失**：纯 MoB-NLL——`NLL = logZ(h) - log p_mix(code(gt))`，即对真值 token 的码取混合对数概率，无教师加权、无蒸馏。熵正则保留小系数（λ=0.001~0.01 防分量坍缩），DAEM 关（T=1）。

**解冻模式（待拍板，§5-Q3 的集群版）**：
- A. 末 N 层 + final RMSNorm 全解冻：最直接检验"顶班"；LR 需小（骨干 1e-5~5e-5 级，头 1e-4 级分组）。
- B. LoRA（r=16~32，attn/mlp 投影，可只挂末 8 层）：漂移有界、优化器状态小、可逆；集群实现用 peft 或手写（~40 行）。

**核心监控指标（2026-09-03 用户修正：MoB 头升任唯一输出头后，原生头指标不再作闸门）**：
1. **验收口径 = 纯 MoB 系统 vs 纯原生基线 PK**：同一 dev 上 MoB-logZ PPL 对比原生基线（本地切片 14.2 / 集群 dev 12.7），加生成样本并排判读——MoB 头是系统唯一输出头，分布漂移不尊重原生流形属预期，原生失准不等于退化；
2. 域外 held-out 的 MoB PPL + 生成判读（灾难性遗忘的等价保险，窄 dev 看不出来）；
3. 原生头漂移 PPL **降级为纯诊断量**（量化"骨干离原生流形多远"，辅助理解共适应强度，不作回退判据）；
4. 级联重排一致率 vs 漂移后原生头（诊断 MoB 头与原生流形的残余耦合度）。

**风险**：① 梯度经 17-bit 瓶颈回传，信号可能太弱（头的表达能力限制骨干的学习）；② 未用顶点（2816 个）质量泄漏随骨干漂移变化；③ 全解冻 catastrophic forgetting；④ V100 显存：fp16 骨干 + LoRA/部分解冻 + 头 fp32 + 激活（grad checkpointing 兜底）。

## 4. 本地试水 protocol（4060，等待续训期间做）

目的：花 ~1 小时拿到"MoB-NLL 能否训骨干"的方向性信号，再决定集群怎么投。

1. 系统：Llama fp16 骨干 + WSD 终版头（fp32）；解冻末 2 层 + final norm（默认）或手写 LoRA r=16 末 4 层。
2. 数据：BabyLM-10M 本地缓存（现成）；batch 4×512，grad checkpointing 备用。
3. 新写 `scripts/p4_backbone_probe.py`（~120 行，复用 mob_common 的 mob_mix_logprob/logZ 数学）：跑 500-1000 步纯 MoB-NLL 训练，分组 LR（骨干 2e-5 / 头 1e-4）。
4. 测三次：步 0 / 中途 / 结束——MoB dev NLL（babylm dev）、原生头 PPL、2 条生成。
5. **通过判据**：MoB dev NLL 下降且原生头 PPL 退化 <2×，无 NaN/坍缩 → 绿灯，写进本文件 §6 并定集群参数。
6. 失败处理：若不稳/退化，试 (a) 只训头+final norm、(b) 更小骨干 LR、(c) LoRA——记录负结果同样落档。

## 7. "容量天花板"判决撤回与升级阶梯（2026-09-04 用户批评，记录在案）

**撤回声明**：此前"容量/几何上限坐实"属过度解读。已证伪的仅是配方级嫌疑（泄漏/耦合震荡/LR 配比/日程）与"LoRA 末 8 层"这一具体配方（饱和于 -5.5%）；头的结构本身未被证伪。

**用户三点批评**：
1. 证据只到配方级上限——冻结骨干蒸馏的 0.774 与 LoRA 联合的 1.94× 都是特定配方的天花板，未触结构；
2. 头的容量账：41.7M 参数的多层非线性头不寒酸——每位置 K×(M+1)≈2304 有效自由度 vs 原生头有效秩 ≤2048 且与嵌入表权重共享（纯线性投影）；n_eff 77/128 的反向解读：~1400 自由度已够用，恰说明自由度充足而非不足；
3. LoRA 失效的机制解释：低秩假设适用于"小样本微调已有预测分布"（领域对齐），而本任务是系统性重塑 h 的输出几何以适配全新表示空间——每层都是高秩变化，**不在 LoRA 舒适区**。已观察证据与此自洽（norm 这个全秩小矩阵贡献显著、翻转 LR 更优、LoRA 饱和早）。

**升级阶梯（把路一步一步走死，全部失败才能判结构死刑）**：
- **Rung 1（已发，job 524864）**：全参解冻末 4 层+final norm（~268M 可训），纯 MoB-NLL，骨干 2e-5 / 头 1e-5，warmup 500，20k 步恒定 LR，同 panel 协议（`p4_joint_train.py --mode unfreeze --n-layers 4`，`slurm_p4_fullft.sbatch`，outdir `runs/p4_fullft/`）。
- **Rung 2**：若 Rung 1 饱和 → 全 16 层+嵌入表解冻（极低 LR，~1e-5 级）。
- **Rung 3（决定性实验）**：若 Rung 2 仍败 → 小规模从零预训练双生子（~124M 规模，BabyLM，MoB 头 vs 原生头同配方同数据对照）——"MoB 结构能否从零学会语言"的终极判决，V100 上仅数小时。
- **续训完成（job 522720，5h12m，2026-09-03）**：peak 2e-4 × 50k 步抛光——终版验收（32,768 位置）归一化 PPL **2.00×**（26.20/13.09）、agree **0.774**（WSD 基线 2.05×/0.770）；panel 尾部仍缓升至 0.778（panel 用小子集，与 32k 位置终值有口径差）。结论：**头的容量上限基本探明**——此配方下 0.77-0.78 agree / ~2.0× PPL 即是天花板，进一步提升须换轴（数据/容量/联合优化）。产物拉回：runs/head_final_cont.pt、train_log_cont.jsonl、p3_cont_metrics.json。
